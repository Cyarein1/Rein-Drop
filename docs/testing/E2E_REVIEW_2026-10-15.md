# End-to-end review: web-first subscription + mobile companion (step 85, 2026-10-15)

## Summary

- **Every automated check that was run passed.** That includes an uncached run of the whole
  monorepo and every API and worker integration suite on a real PostgreSQL. The new **end-to-end
  journey test** runs all 15 journey stages plus the 11 extra scenarios: **23 / 23 checks** passed.
- **Two defects found and fixed.**
  - **D1 (security, medium):** with real Stripe billing, any account could grant itself a paid plan.
  - **D2 (test reliability):** one listing-photo test failed about 1 run in 64.

  FCM, Entra). They need owner set-up. Section 6 lists what remains to check by hand.

## 1. How the journey was tested

`apps/api/test/journey.int-spec.ts` runs one account through everything, using:
- **API:** the real Nest application;
- **Worker:** the real pipeline classes (scheduler, marketplace search, AI analysis on the mock
  provider, alert writer, notification outbox, access gate, push sender);
- **Database:** a real PostgreSQL (preview database, port 5433);
- **Identity:** Entra External ID tokens signed with a test key, so the first sign-in creates the
  account as it does in production;
- **Billing:** the official Stripe SDK talking to an in-memory fake Stripe;
- **Push:** the worker's push simulator, through the real outbox and access gate;
- **Clients:** "web" and "mobile" are two separately signed-in clients (separate tokens) of the same
  account, calling the same API the apps call.

What the API returns to each client is checked here. How each app **renders** it is covered by
component tests: mobile (jest-expo) for deal cards, economics, load states, navigation and the push
bridge; web (vitest) for nav, billing view, access and companion wording.

## 5. Defects found and fixed

| ID | Severity | Defect | Fix |
|---|---|---|---|
| D1 | Medium (security / billing) | `POST /billing/dev/confirm` (development fake billing) was only turned off when `NODE_ENV=production`. In any other environment wired to real Stripe (test, staging, preview) **any signed-in account could give itself a paid plan for free**. Found by the journey's bypass test | `dev-billing.controller.ts` answers 404 when `NODE_ENV=production` **or** `BILLING_PROVIDER=stripe`. The web only uses that endpoint in development billing mode, so nothing else changes |
| D2 | Low (test reliability) | `sell.int-spec` "tampered link" replaced the signature's first character with `x`. When the signature already started with `x` (about 1 in 64 runs) the link stayed valid and the test failed | The whole signature value is replaced |

Also changed: the API's type-check root (`apps/api/tsconfig.json` `rootDir: ../..`), so the journey
test can run the worker's real classes. The build config is unchanged.
